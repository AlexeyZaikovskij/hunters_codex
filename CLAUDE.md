# Hunters Codex (рабочее название)

Браузерная пошаговая тактическая RPG с элементами MMO. Мир вдохновлён книгой «Кодекс Охотника», но **оригинальный**: свои названия, ранги, фракции. Игра планируется к **монетизации**, поэтому имена и термины из книги не используем.

Автор — один человек, немного понимает в программировании, дизайнера нет. Упор на **наполнение и механики**, а не на графику. Код в основном пишет Claude.

## Деплой и база
- **Прод:** https://hunters-codex-five.vercel.app (Claude может проверять его сам).
- **Vercel** автодеплоит из GitHub: `main` → прод (`dev` → превью, сейчас не используется). Сборка — `vite build` без tsc (`vercel.json`); типы и тесты проверяет GitHub Actions (`.github/workflows/ci.yml`), не блокируя деплой.
- **Supabase:** клиент в `src/lib/supabase.ts`; ключи `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` — в `.env.local` (не в git, шаблон `.env.example`) и в переменных окружения Vercel. Без ключей игра работает офлайн; статус сервера показан на экране пробуждения.
- **Миграции** лежат в `supabase/migrations/` (001, 002, …). **Применяет их автор вручную** в Supabase → SQL Editor; Claude кладёт файл в буфер обмена (`Get-Content -Raw -Encoding utf8 файл | Set-Clipboard`) и явно говорит порядок «миграция ↔ фронтенд».
- Живую БД Claude **только читает** (anon key). Писать — через миграции. Service role key Claude не запрашивает и не хранит.
- Бесплатный Supabase засыпает через ~7 дней без запросов → `.github/workflows/keep-supabase-alive.yml` пингует базу раз в день.
- Проект Supabase: `https://abbyelcjdhmwchvtrhfl.supabase.co`, ключ — новый формат `sb_publishable_…` (в запросах REST достаточно заголовка `apikey`). Применённые миграции: **001**.
- На новом ПК: скопировать `.env.example` в `.env.local` и вписать URL и publishable key (они есть в `keep-supabase-alive.yml`).

## Ключевые решения (кратко)
- **Жанр боя:** тактика на клеточном поле в духе Wakfu/Dofus (очки действия, очки передвижения, позиционирование). Игрок управляет **одним персонажем**; позже возможны призывы, клоны, миньоны.
- **Мир — Atrium:** столкновение технологий и магии. Магия и материалы приходят из **Червоточин** (класс опасности, прорывы, случайные события). Одарёнными **рождаются**; многие дары небоевые. Позже — расы: оборотни, вампиры, ящеролюды, эльфы.
- **Техника в Червоточинах не работает**, магитехника работает. Внутри — холодное оружие, луки, арбалеты, метательное, магия. Вне Червоточин (прорывы, арена) огнестрел работает. Лучшее снаряжение — из материалов Червоточин.
- **Закрытие Червоточины:** полная зачистка, победа над боссом или уничтожение источника (кристалл/артефакт).
- **Тон:** немного героический (защита человечества от вторжения), обязательно с юмором.
- **Школы магии:** Огонь (площадь, горение), Свет (лечение, щиты; силён против нежити), Кровь (жертва здоровьем + похищение жизни), Пространство (перемещения, урон от столкновений и падений). **Усиление тела** — базовая школа, доступна всем без склонности. На рассмотрении: Энергия.
- **Три оси развития:** уровень (очки характеристик), мастерство (владение школой), ранг (испытания, доступ к контенту).
- **Склонность:** случайная при регистрации, равноценная по силе; развивать можно и другие школы. Смена склонности будет (в том числе как монетизация). **Редкое пробуждение** — шанс при первом повышении ранга.
- **Фракции:** Технократия, Империя, Вольный союз, Орден. Над ними — нейтральная **Служба контроля Червоточин**: выдаёт ранги (признаются всеми), владеет стартовой территорией. Репутация у одной фракции влияет на отношение других.
- **Бой:** ОД/ОП по инициативе, плюс **мана**, которая почти не восстанавливается (усталость); удар оружием — отдельное действие без маны, сила от снаряжения. Поле — сетка с препятствиями, **без высоты**. На старте школы: базовая + склонность, остальные — на высоких рангах. 8 слотов умений.
- **MMO-lite:** без общего мира с перемещением; город/база — экраны, бои — инстансы, PvP — арена (пошаговое, сервер принимает ходы).

## Стек
- TypeScript + Vite, React (интерфейс), Phaser 3 (поле боя), Vitest (тесты)
- Позже: Supabase — аккаунты, сохранения, сервер
- Контент (монстры, умения, предметы) хранится **в данных** (`src/data/`), а не в логике.

## Запуск
```
npm install      # один раз на новом ПК
npm run dev      # игра на http://localhost:5173
npm test         # тесты движка
npm run build    # проверка типов и сборка
npm run balance -- 200 E   # симуляция боёв (без аргумента карты — учебная; E/D — случайные Червоточины)
npm run maps -- D 3        # напечатать примеры сгенерированных Червоточин
npm run icons              # пересобрать src/data/icons.ts после добавления иконок в данные
```

## Структура кода
- `src/engine/` — боевой движок на чистом TS, **без графики** (чтобы тот же код потом работал на сервере для PvP). `battle.ts` — правила, `ai.ts` — ИИ монстров, `grid.ts` — сетка, путь, линия обзора, `rng.ts` — детерминированный рандом.
- `src/data/` — умения, оружие, монстры, карты. Новый контент добавляется здесь. `mapgen.ts` — генератор Червоточин по зерну (стили, класс опасности, состав монстров).
- **Иконки:** набор game-icons.net (CC BY 3.0 — **обязательно указывать авторство**, строка есть внизу экрана настройки). У умений, оружия и монстров поле `icon` с именем иконки (искать на game-icons.net); затем `npm run icons` — в `src/data/icons.ts` попадают только используемые. Тест `icons.test.ts` ловит забытые иконки.
- `src/game/` — связка: `session.ts` (движок ↔ интерфейс), `BattleScene.ts` (Phaser: отрисовка и анимации), `PhaserView.tsx`.
- `src/ui/` — React-экраны: выбор склонности и оружия, экран боя.
- В dev-режиме в консоли браузера доступны `window.__session` и `window.__game` для отладки.
